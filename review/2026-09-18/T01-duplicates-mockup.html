2 — what counts as a duplicate
  • Same name, after the staging prefix (NEW) / (UP) is stripped. Two policies cannot legitimately carry one name.
  • A version is part of the name, so v1.0 beside v3.0 is not a duplicate — that is the older-version case and it stays in 🧹 Housekeeping.
  • Not a duplicate: the same CA number with a different name. That is a number clash, and 🧬 Baseline already reports it. Never listed here.
  • Listed, never merged: a set whose copies ENCA could not read in full — the comparison has nothing to go on, and it says so.
  • Each set is compared with the same engine as ⇄ Compare versions (PolicyCompare), so the verdict names exactly what differs: state, assignment, conditions, grant or session controls.
  • Three verdicts: identical (only the state differs, or nothing does), assignment differs (mergeable, and the choice is yours), controls differ (never merged automatically).
