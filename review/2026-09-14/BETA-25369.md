## Acceptance findings and fixes

1. **Large worker responses blocked the browser.** Before the change, 50k × 40 and 250k × 8 coverage fixtures produced long tasks of 1,019 and 1,323 ms. Coverage now transfers input and results in batches of 500 with an event-loop yield between messages. The worker sorts the entire report before sending it back; previously each computation chunk was sorted separately. The two-million-evaluation limit remains.
2. **Mobile Escape did not close navigation.** Escape now closes the drawer, updates `aria-expanded` and returns focus to the menu button.
3. **Local container returned 403 for owner-only files.** The checkout contained mode-600 HTML/JavaScript. Docker COPY preserved those modes, so nginx's worker could not read them. Build steps now set site directories to 755 and files to 644. The entrypoint remains executable outside the served site. The duplicate HTML gzip declaration was removed.
4. **Narrow identity cards clipped content.** The mobile grid can shrink its text column, long identifiers wrap, facts use normal text flow and the channel ribbon has header space. Tests check both page overflow and the identity card itself.

The CLI authentication status and `/organization` identity matched the user-specified tenant before data reads. Requests used the installed Microsoft Graph skill and delegated read-only permissions. Only aggregate outcomes are committed; raw tenant policy bodies, IDs and sign-in samples remain outside the repository.

- Active subscription evidence: P1 and P2, Intune and a Cloud Apps plan detected; Workload Premium not detected; Governance/Purview remained unknown. Subscription evidence does not establish per-person licence compliance or Defender connector/role access.
- Organization, subscriptions, users, groups, stable/beta policies, named locations, audit log, stable sign-in query and beta non-interactive preview returned **HTTP 200**.
- Users, groups, logs and audit checks were bounded samples; continuation links were present where applicable. They are not complete tenant inventories. No Graph endpoint was called with a write method.
- The non-interactive preview query returned an event whose type was `nonInteractiveUser`; that verifies actual event availability in this tenant, not P1-only availability.
- Four named locations were returned. Stable Graph returned 98 policies; beta returned 105. Repeated near-simultaneous reads confirmed the same 98/105 split, with zero stable-only policies and seven beta-only disabled policies. The reason is unresolved. Existing beta policy routing is retained; do not migrate it blindly to v1.0 or equate the two inventories.
- These are **CLI/API contract checks with the delegated account**, not end-to-end sign-in and execution of every ENCA tool under its own app registration.

Official [stable policy-list documentation](https://learn.microsoft.com/en-us/graph/api/conditionalaccessroot-list-policies?view=graph-rest-1.0) and [beta policy-list documentation](https://learn.microsoft.com/en-us/graph/api/conditionalaccessroot-list-policies?view=graph-rest-beta) describe the separate contracts. They do not establish the cause of this tenant's observed difference.
