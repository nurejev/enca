## Deliberate limits and remaining work

- **Work package 4, live beta acceptance, remains pending.** No P1-only/P2-only live tenant, Intune/Defender/Workload combinations, restricted-AU write or group-migration write was tested. No production deployment, GitHub push, container deployment or real-tenant change occurred.
- Coverage analysis refuses selections above **two million user-policy evaluations**. Wave reads up to **25,000 members**, reduced for larger policy sets to stay within the same evaluation budget. A Wave above its limit is explicitly partial; choose a smaller group for complete evidence. This is scoped large-tenant operation, not an unbounded 250k-user tenant-wide matrix.
- Worker computation remains subject to browser memory, input/result serialization and rendering. The 50k/250k-user and 100k/1m-event acceptance lanes, worst-case membership/policy shapes, heap and long-task measurements are pending.
- The shared four-slot limiter applies to `gget` directory reads. Existing batch/hunting/ARM paths retain their source-specific scheduling. It is not a universal adaptive multi-source scheduler. Existing GETs without a supplied signal stop at the next checked read boundary; all requests are not instantly abortable. Write requests retain existing item-boundary/ledger behaviour.
- First-page results are implemented for report-only impact. Other tools show immediate progress/counts and publish a result when their required evidence is available. A universal progressive result renderer and per-section retry UI remain future extensions.
- Remaining beta endpoints and optional-source contracts are listed in `P1-ENDPOINT-CONTRACT.md`. Capability metadata describes the support contract; it does not prove every tenant/role/source combination is available. Unknown product evidence can conservatively block a legitimate write. The check does not certify per-person licensing.
- A group copy readback can conservatively stop during replication delay. The replacement stays staged; original policy references remain unchanged. Recheck before proceeding. This is intentional rather than interpreting missing verification as success.
- A second administrator can consume a policy slot between preflight and write. Server errors and per-item ledgers remain necessary. Some auxiliary display-name/nesting-description reads remain optional; do not mistake unavailable descriptive enrichment for complete relationship evidence.
- Full narrow-screen, dark/automatic theme, all brands, keyboard, reduced-motion and assistive-technology checks remain pending.
