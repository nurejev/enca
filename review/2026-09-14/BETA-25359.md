# ENCA beta 25359 — consistent tabbed tool layout

Based on beta `cadfeea`. Fixes the layout shifts reported when switching between A user, A group and Compare users.

## Changes

- Host subtabs keep the tab row at the same viewport position when switching. They show the destination's opening controls instead of restoring an unrelated deep result scroll position. Other tool navigation retains its existing scroll memory. Rapid transitions cannot apply a stale queued scroll, and keyboard focus follows the selected tab without scrolling again.
- A stable scrollbar gutter preserves the content width between short and long screens. Tool screens have a common minimum viewport height so a short destination can retain the same tab-row anchor.
- The three Who is subjects share compact intro cards, with the existing explanation, scope and permission information available through a keyboard-accessible About this tool disclosure.
- The wave's deployment/persona chips are now a compact group dropdown. Full names, member counts, unknown counts and disabled missing groups remain available. Selecting a group uses the existing read flow; arbitrary name/ID lookup remains available.
- The wave log-source selector now mounts on the current toolbar rather than the removed `wvToolbar2`. Log-source controls are inserted ahead of filter/window controls in keyboard order.
- Active host toolbars are observed for height changes, so wrapping controls and newly visible export actions update the sticky offsets.
- Tool versions: T36 1.2, T37 0.8.3, T18 1.0.3. Build/assets/changelog and Waiting for production item 195 accompany the change.

## Completed validation

- **35 offline tests passed**, including a new integration guard requiring every log-source selector target to be an existing toolbar.
- Application scripts parse; release/asset/promotion metadata and local assets pass existing checks.
- Toolbar structure: 34 tool screens, 33 toolbars, expected slot order, with the existing Protect exception. Plain-text and Git whitespace checks pass.
- Isolated Edge browser in demo mode: after scrolling a long user result to 900px, switching Group → Compare → User keeps the tab row at y=113px. Rapid switches keep the final target and focus. At a 1600px viewport all three use x=292px and width=1265px, their closed intro cards are 110px high, and toolbar tops align at y=298px.
- Selected an existing demo group through the new dropdown: the actual group read completed, the selection remained visible, and the report/export actions appeared. No tenant writes were performed.
- Keyboard Enter opens and closes About this tool. No browser page errors.
- Checked Who is tabs at 1600, 1280, 1024 and 390px: no horizontal document overflow. Measured sticky offsets include the active toolbar's actual height after wrapping.
- Also checked desktop alignment and overflow across Checks (4 tabs), Baseline (2), What-If (2) and Policy building blocks (5).
- Desktop group-result and mobile comparison screenshots inspected.

## Remaining validation

Toolbar heights can differ where a subject needs more controls; the shared top alignment and sticky offsets accommodate wrapping. Previous beta validation requirements remain in their corresponding queue items. No Docker deployment validation was performed in this update.
