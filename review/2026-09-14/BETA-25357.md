# ENCA beta 25357 — implementation and validation

Implemented on branch `beta`, starting at `8ec00e8`. This is beta work; production has not been promoted or pushed.

## Delivered design

- **Policy workspace:** list by default, concise policy labels beside unchanged original names, real state counts, persistent tenant/demo context, and a side inspector with scope, exclusions, controls and original JSON. Cards, matrix, selection and existing actions remain available.
- **Checks evidence desk:** severity-ordered findings beside the actual assessment, recommendation and affected policy. Configuration scorecard and persona matrix are expandable. Context-read limitations appear in the screen and Markdown report.
- **Guided rollout (T40):** scope → plan → observed impact → go-live review. Existing policy selection, baseline comparison, prerequisite guide, backup, import, group review, report-only impact and state confirmation are connected. Acknowledgements are manual, session-only, and cleared when selection or the policy snapshot changes.
- **Shared navigation and accessibility:** compact green desktop navigation, a mobile menu, native home-launch buttons, visible focus, dialog roles and labels, focus containment/restoration, and visible close controls. Long About content is collapsible.

## Remaining beta validation

The local Docker daemon was unavailable. Image startup and live HTTP-header checks are configured in CI but were not executed locally. No real tenant writes or new consent flows were exercised; promotion queue items contain the required test-tenant scenarios. Offline Graph fixtures do not prove live Graph normalization, conditional-access step-up, or permission behavior.

The local simulator intentionally leaves compound device expressions unresolved. Restricted external-user scope remains unknown when type/home-tenant metadata is unavailable. The rollout is an assisted route through existing tools, not an automatic deployment approval system. Policy replacement spans multiple API calls; after a partial failure, inspect the reported new policy before retrying.


The first updates the beta branch in `nurejev/enca` and its beta container workflow. The second updates the beta-site repository `nurejev/enca-beta`. Neither command pushes the production `main` branch of `nurejev/enca`.
