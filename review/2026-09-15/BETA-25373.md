# ENCA beta 25373 — compare Housekeeping policy versions

Implemented on beta from `1c4d82d` (25372). Waiting for production item **208**. This change adds read-only comparison and records Codex co-authorship on the new implementation commit. Existing published commits are not rewritten. No remote push, deployment, tenant request or policy deletion was performed.

## 1. Delivered behavior

1. Every older/newer policy pair in Housekeeping has **Compare versions**, including review-only pairs. Both policies appear side by side with one field per row. Changed rows are marked in text and color; array entries explicitly indicate Added or Removed relative to the newer version.
2. The default **Differences only** filter shows changed fields. Clearing it also shows unchanged settings, including the common three-hour sign-in frequency in the supplied CA008-style example. Policy names and states are compared; policy IDs, timestamps and top-level OData metadata are omitted.
3. Users, groups, roles, resources, locations and other supported references use the tenant resolver already built during policy loading. Resolved names retain the underlying identifier, so two objects with the same name remain distinguishable. No additional Graph calls or consent are needed.
4. The comparator shares normalization with Housekeeping eligibility: object keys and array order do not create differences, unknown preview properties are retained, and incomplete payloads produce an explicit limitation. Compare does not change deletion eligibility or select a policy.
5. Closing the comparison returns to Housekeeping with its existing selection. The dialog supports Escape and the existing modal focus handling. On narrow screens the table scrolls horizontally inside the dialog without widening the page.
6. The new commit includes `Co-authored-by: Codex <noreply@openai.com>`, keeping Mihai Monte as primary author. This records attribution in Git; GitHub profile association and contributor-list display are external behavior, not a tested outcome.

## 2. Passed validation

1. **104/104 offline tests**, including seven new cases for field-level additions, removals, states, metadata and ordering, unknown properties, missing data, same-name/different-ID references, null/absent/false/empty distinctions, object type changes, HTML escaping, session controls and arrays of objects. Existing nine Housekeeping classification tests still pass. Evidence: `tests-25373.txt`.
2. Local Edge browser acceptance at **1440px/light** and **390px/dark**, all external requests blocked. A disabled review-only row can open Compare; named additions/removals are correct; Differences only hides equal controls; All settings shows them. Escape closes only Compare, preserving the checked cleanup candidate.

Both retain a three-hour sign-in frequency. These are fixtures, not a claim about the actual tenant's unread raw policy payloads.
4. Existing deletion handoff checks pass: stable selected ID after reorder, rejection after eligibility changes, default backup, typed confirmation and extra acknowledgement for On policies. No delete action is executed.
5. Zero page exceptions. Desktop/mobile screenshots were inspected; the mobile table scrolls while the dialog stays within the viewport. Evidence: `housekeeping-compare-25373.json`, `housekeeping-compare-desktop-25373.png`, `housekeeping-compare-mobile-25373.png`.
6. Toolbar order (34 screens, 33 toolbars, existing Protect exception), plain text, JavaScript syntax and whitespace checks pass. Build/cache keys, T01 version, changelog and queue 208 are updated together.

## 3. Limits and pending checks

Live-tenant acceptance, other browser engines and screen-reader testing were not performed. The comparison describes the loaded snapshot; it does not establish which policy should be enforced or removed and does not refresh tenant data. Existing P1-only, large-tenant network-delay and tenant-write production gates remain open.

## 4. Reproduction

Run `node --test tools/*.test.cjs`, `node tools/check-toolbar-order.js`, and `node tools/check-plain-text.js`. Start the repo on loopback port 8769. With `PLAYWRIGHT_MODULE` pointing to the installed Playwright dependency, run `node tools/housekeeping-browser.cjs`. Set `ENCA_EVIDENCE_DIR` to choose the evidence folder.

Fixtures are injected only into the test browser's intercepted local app response; shipped code has no test hooks.
