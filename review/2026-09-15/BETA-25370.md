# ENCA beta 25370 — search, screen and export acceptance

Status: implemented on beta for the next release. No push, production deployment or tenant write. Starting commit: `58677b5` (25369). Help > Waiting for production item **205** belongs to the existing `p1-scale-1-3` group. Earlier acceptance is retained with dated follow-up notes.

## 1. Policy inventory difference — resolved

The existing delegated sign-in was valid and matched the user-designated test tenant. Read-only calls repeated **98 policies from v1.0 and 105 from beta**, neither with a continuation link. Every one of the seven beta-only policies was then read individually through both versions:

- All seven v1.0 detail requests returned **HTTP 400 / BadRequest**, with service message **1037** requiring beta because the policy contains preview features.
- All seven beta detail requests succeeded. The policies are disabled and none has a deletion timestamp.
- The explanation is preview-only policy compatibility. This is not evidence of deleted or lost policies. The exact preview property of each policy was not isolated, and is unnecessary to establish the server's explicit version requirement.
- ENCA already reads policies through beta; that route is retained. Do not substitute a v1.0-only inventory or claim the two versions have equivalent coverage.

Only aggregate evidence is committed in `policy-inventory-25370.json`. Raw policy responses were removed from temporary storage. No policy names, tenant identifiers, user lists, tokens or sign-in events are included in that artifact. This tenant has P2/Intune: these calls do not certify P1-only operation or ENCA's own app registration.

## 2. Screens and exports

The local browser suite exercised **34 screen/view states × 4 combinations = 136 checks**, using Edge, light/dark themes and 1440/390 px viewports. This includes coverage analysis as a separate view of the policy screen. There were **zero page exceptions and zero horizontal page overflows** in those states. Horizontally scrollable result tables are intentionally retained; page-width checks do not mean every column fits at once.

The suite attempted 108 report/export cases. **96 passed**: 92 rendered Markdown report cases, plus two parsed JSON and two CSV downloads. The remaining 12 were unpopulated Checks, CIS and Drift report cases across the four combinations. A supplemental test then ran populated Checks and CIS and opened their reports, plus the folded Teams devices tool and its report. Drift comparison/export still needs a prior snapshot and representative change comparison; it is not recorded as passed.

Findings fixed:

1. Tool number/version badges split across lines on narrow screens; each badge now remains one unit.
2. A wide report table made the whole report body scroll horizontally. Each table now has its own keyboard-focusable scroll region; surrounding prose stays within the viewport.
3. An escaped literal pipe in a table value was parsed as another column. The report viewer now preserves it in the value and keeps HTML escaped.

The supplemental mobile fixture confirms a long table can scroll while the report body remains **267 px wide**, and a `Finance | Legal` name remains in one cell. Audit and report screenshots were visually inspected. The test scripts block non-loopback requests. The supplemental script injects fixture hooks into the local browser response only; these hooks are not shipped in app.js.

These are demo/fixture checks, not an all-tool live-tenant certification. No new DOCX/PDF export certification, screen-reader audit, Safari/Firefox native suggestion-popup acceptance, or every possible state/filter combination is claimed. The prior custom-brand/auto-theme/container/scale evidence remains in BETA-25369; those suites were not all rerun for this release.

## 3. Search/autofill audit and fixes

Here autofill means selectable suggestions while typing, not browser-saved personal information. **16 local result filters** now use the shared helper:

| Tool | Field | Suggestions from already loaded results |
| --- | --- | --- |
| T16 Changes / audit | auSearch | Resource, actor name/UPN, affected member, activity, changed field |
| T01 Policies | searchBox | Policy name |
| T03 Gap analyse | anSearch | User name / UPN |
| T09 Exclusions | exSearch | Entity name/ID, or users/UPNs, or risk policy names for the selected view |
| T12 CA groups | cgSearch | Group name/ID and loaded member names/UPNs |
| T10 Baseline | blSearch | Policy number, baseline name, tenant name |
| T13 Simulations | vaSearch | Simulated policy names |
| T39 Apps without service principal | sgSearch | App name/ID and relevant policy names |
| T15 Locations | loSearch | Location names |
| T22 Contexts | acSearch | ID, name, description |
| T23 Strengths | asSearch | Name, description |
| T25 Terms of use | tuSearch | Agreement name |
| T24 Deleted items | rcSearch | Deleted policy/location names |
| T27 Restricted AUs | ruSearch | AU name, description |
| T31 Licence gap dialog | lgUserSearch | Loaded user name / UPN |
| T19 Group sweep | guSweepSearch | Loaded group names |

T16's filter also matches actor UPNs and affected member names, so those suggestions produce results. Existing identity pickers and sign-in/report-only/session searches already had suggestions and remain in place; the latter three also returned options in browser acceptance. Form criteria such as a prefix to read, IP addresses, write confirmations and new-object names are not result filters and were not assigned arbitrary suggestions.

Suggestions match before the **60-option limit**, deduplicate case-insensitively, and yield after every 1,000 candidate fields. A fixture finds identity 249,999 in a 250,000-identity source. This is not a cap on the underlying result. No additional Graph request, subscription requirement or persisted name history was introduced.

The helper checks query/tenant context and cancellation again after awaiting local work. Blur clears options; a picked option is not rewritten. T19 also retains the cursor while rebuilding its search row and cancels the new list after a pick. The supplemental browser test verifies selection, subsequent editing, filtered row counts and the modal-only T31 field. T19 tenant reads are disabled in demo; its loaded-result behavior was therefore tested with an explicitly injected fixture, not a live sweep.

Native popup appearance and mouse/arrow selection vary by browser. Automated selection checks exercise the input event and result behavior; they do not certify each operating system's native datalist popup.
