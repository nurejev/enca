# ENCA beta 25371 — workspace subtab restoration

Implemented on beta for the next release, starting from `3950621` (25370). No push, production deployment or live tenant operation. Waiting for production item **206** records this navigation fix separately from the P1 acceptance group.

## 1. Problem and behavior

The top-level workspace tab called the host tile's default open handler. Returning to **Sign-in log** therefore opened **T17 Failures**, even after leaving **T26 Report-only impact** during a read. Other shared subtab hosts followed the same path. Browser Back only toggled the screen, leaving the active workspace tab/sidebar out of sync.

Each open workspace tab now remembers its last visible shared subtab. The top bar, sidebar, plus menu and automatic neighbour selection after closing another tab use that remembered destination. The existing tool's open function restores its current content; reads are not restarted by the new routing helper. Hidden production-only restrictions are checked before resuming a destination.

The eight hosts covered are Sign-in log, Changes, Gap analyse, Who is to CA, What-If, Checks, Policy building blocks and Baseline — **23 shared subtabs** in this beta. This does not introduce persistence across a browser reload. Closing a workspace tab forgets its remembered subtab. Explicit tool/deep-link open functions still choose their intended destination; opening a host directly from its home tile can intentionally select the default.

Browser history now records the host/subtab and tool alongside the screen. Back/Forward restores that historical destination and its active navigation state. Policies and Coverage have separate history entries even though both use `screen-list`. Existing modal/expanded-view Back handling is retained.

## 2. Verification

**88/88 offline tests passed**, including three new routing tests for remembered subtabs, hidden destination fallback, and closed/removed destination fallback. See `tests-25371.txt`.

`tools/navigation-browser.cjs` ran against the local demo in Edge at **1440px/light** and **390px/dark**, blocking all external requests:

1. Every one of the 23 subtabs restored through both the top bar and sidebar in both variants: **92 return-path checks**.
2. T26's local analysis job was deliberately paused through `AnalysisJobs.run` while the actual run wiring stayed active. Switching to Checks and back restored T26, showed its Stop control and left the analysis invocation count at **one**. Completing the job published the result successfully.
3. The selected source (`entraall`), period (30 days), Per user view, search text and rendered result survived a completed-result round-trip, with no extra analysis invocation.
4. The plus menu and closing the active neighbouring workspace tab returned to T26.
5. Browser Back/Forward selected the historical T17/T26 destination and correct active top tab. Policies/Coverage Back/Forward restored the correct tool and visible view.
6. An explicit host open selected its default, and closing/reopening the workspace tab cleared the old remembered subtab.
7. Both variants completed with **zero page exceptions**. Evidence: `navigation-25371.json` and the desktop screenshot.

The delayed operation is a local analysis fixture, not a live throttled Microsoft Graph request. Live network-delay acceptance, other browser engines and screen-reader behavior were not run for this fix. Previous large-tenant/P1-only/write acceptance gates remain open; this report does not certify them.

Toolbar order (34 tool screens / 33 toolbars, existing Protect exception), plain-text checks, JavaScript syntax and `git diff --check` passed. Build, asset cache keys, affected tool versions, changelog and queue 206 were updated together.

## 3. Reproduction

Start the repo on loopback port 8769, set `PLAYWRIGHT_MODULE` to the installed Playwright module, then run:

```sh
node --test tools/*.test.cjs
node tools/check-toolbar-order.js
node tools/check-plain-text.js
node tools/navigation-browser.cjs
```

Set `ENCA_EVIDENCE_DIR` to choose the browser evidence output directory. The browser suite uses only demo data; no sign-in is required.
