# ENCA beta 25372 — Housekeeping version review

Implemented on beta from `d9b9de4` (25371). Waiting for production item **207**. No remote push, deployment, tenant access or policy deletion was performed.

## 1. Behavior

Housekeeping previously required the older version to be Off. It therefore missed the supplied CA110 example: v1.0.1 is Report-only, while v1.0.2 is Off with a different group assignment. A higher version alone does not establish equivalent protection.

All older versions with a higher version of the same CA number now appear, including On and Report-only predecessors. The highest version is shown beside each predecessor. The dialog explains differences in state, names, assignments/exclusions and conditions/controls. It considers the entire loaded inventory, independently of the Policies search filter. This is version-family detection; it does not attempt to identify equivalent unversioned policies or unrelated CA numbers.

Deletion review is available only when the older version is Off, the newer version is On, the normalized names match, raw configuration is available and equal, and the highest successor is unambiguous. Equality ignores IDs, display name, state, timestamps and top-level OData metadata; it normalizes object-key and array order and retains unknown preview properties. Differences are treated conservatively as review points. A candidate can still be needed for rollback: nothing is selected automatically.

Selections use policy IDs, and eligibility is checked again against the loaded inventory before entering the existing backup/typed DELETE dialog. A changed or missing candidate returns to review. This is not a fresh server read or a guarantee against concurrent tenant changes. The existing shared deletion dialog also now recognizes the model's `on` state, restoring its additional enforcement-removal acknowledgement.

The dialog uses stacked policy details and a wider desktop panel so long names and review reasons remain readable on mobile. No additional Graph calls, permissions or licence requirements were introduced.

## 2. Passed validation

1. **97/97 offline tests**, including nine new Housekeeping cases: screenshot pair, matching Off/On pair, active predecessor and inactive successor states, raw-state precedence, dotted numeric versions, separate CA110/CA1100 families, ordering/metadata normalization, different names/controls/preview fields, incomplete payloads, multiple highest successors, equal and missing versions. Evidence: `tests-25372.txt`.
2. Local Edge browser acceptance at **1440px/light** and **390px/dark**, with all external requests blocked. The screenshot pair appears even when no cleanup candidates exist; review rows are disabled and nothing is prechecked. Status and assignment reasons are visible.
3. Reordering the inventory retains the chosen policy ID. Changing eligibility while the dialog is open prevents entry to deletion confirmation. The ordinary confirmation retains its default backup and typed DELETE guard. An On policy requires the extra acknowledgement. Tests stop before executing deletion.
4. Both browser variants report zero page exceptions. Desktop and mobile screenshots were visually inspected after fixing a narrow-column layout issue. Evidence: `housekeeping-25372.json`, `housekeeping-desktop-25372.png`, `housekeeping-mobile-25372.png`.
5. Toolbar order (34 screens, 33 toolbars, existing Protect exception), plain-text checks, JavaScript syntax and whitespace checks passed. Build/cache keys, T01 version, changelog and queue were updated.

## 3. Not tested / release limits

Live-tenant acceptance, live deletion/restore, other browser engines and screen-reader testing were not run. Existing P1-only, large-tenant network-delay and approved tenant-write acceptance gates remain open. This local UI correction does not complete those broader production gates.

## 4. Reproduction

Start the repo on loopback port 8769. Run `node --test tools/*.test.cjs`, `node tools/check-toolbar-order.js`, and `node tools/check-plain-text.js`. With `PLAYWRIGHT_MODULE` pointing to the installed Playwright dependency, run `node tools/housekeeping-browser.cjs`. Set `ENCA_EVIDENCE_DIR` to choose the output folder.

The browser test injects synthetic policies into its locally intercepted app response only; shipped app code contains no test hook. No sign-in is required.
